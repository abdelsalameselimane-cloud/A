# نظام الاشتراكات — دليل الإعداد والنشر

## الملفات
| الملف | الدور |
|---|---|
| `index.html` | التطبيق الحالي + صفحة الاشتراكات والدفع والإشعارات وبوابة المزايا (كل وظائفه القديمة كما هي) |
| `admin.html` | لوحة الإدارة المنفصلة (مستخدمون، اشتراكات، مدفوعات، خطط، إعدادات، إحصائيات، تدقيق) |
| `firestore.rules` / `firestore.indexes.json` | قواعد الأمان والفهرس المطلوب |
| `functions/` | Cloud Functions: كل ما يغيّر الاشتراك يتم هنا فقط (Admin SDK) |
| `scripts/make-admin.js` | إنشاء المدير الأول وزرع الخطط الافتراضية |
| `tests/rules.test.js`, `functions/test-logic.js` | الاختبارات |

## بنية قاعدة البيانات
- `users/{uid}` و `users/{uid}/chunks` — **بنية المزامنة الموجودة أصلًا، لم تُغيَّر** (لذلك لم أضع ملف الاشتراك داخل `users` لأن التطبيق يعيد كتابة هذا المستند بالكامل).
- `subscriptions/{uid}` — الاشتراك (حالة، خطة، بداية، نهاية، مدفوع، آخر دفعة). **قراءة فقط للمالك.**
- `plans/{id}` — الخطط (اسم/وصف بثلاث لغات، سعر، مدة، مزايا، حدود، مفعّلة).
- `paymentRequests/{id}` — طلبات الدفع (لقطة من سعر الخطة وقت الطلب). `paymentProofs/{id}` — الإثبات (للمدير فقط). `paymentHistory/{id}` — سجل المدفوعات المؤكدة. `paymentLocks/*` — أقفال منع التكرار.
- `adminSettings/global` — فترة السماح، أيام إشعار الانتهاء، تعليمات الدفع، إلخ.
- `notifications/{uid}/items/*` — إشعارات داخل التطبيق. `auditLogs/*` — سجل التدقيق.

## ما الذي يُفرض من الخادم فعلًا؟
1. **كل كتابة** على `subscriptions/plans/payment*/adminSettings/auditLogs` مرفوضة في القواعد؛ تتم عبر الدوال فقط.
2. **المزامنة السحابية** (`users/**`): القواعد تسمح بالكتابة فقط لاشتراك `active` + `sync=true` + `expiresAt` لم يمضِ (+ مدة السماح). القراءة دائمًا مسموحة للمالك، فلا تُحجب بياناته أبدًا.
3. **صلاحية المدير**: Custom Claim `admin` (لا يمكن للمستخدم تعيينه)، وتُعاد قراءته من Firebase Auth في كل دالة إدارية.
4. **الانتهاء** يُحسب من `expiresAt` في القواعد وفي `getAccess`، ولا يعتمد على مهمة مجدولة.

> **حد صريح:** المزايا التي تعمل بالكامل داخل المتصفح (التقارير/الإحصاءات، تصدير xlsx، حدّ عدد المستندات) لا يمكن لأي خادم منعها ممّن يعدّل كود الصفحة. هي مقفلة في الواجهة فقط. ما يحميه الخادم فعلًا هو المزامنة السحابية. إن أردت حماية التقارير حقًا فيجب نقل توليدها إلى دالة سحابية.

## الإعداد والنشر (مرة واحدة)
1. **Blaze:** Cloud Functions تتطلب خطة Blaze (الدفع حسب الاستخدام، ولها حصة مجانية). فعّلها من Firebase Console.
2. تثبيت الأدوات: `npm i -g firebase-tools` ثم `firebase login` ثم `firebase use youyou-f869f` (أو `firebase init` واختر المشروع الحالي دون استبدال ملفاتي).
3. **انسخ قواعدك الحالية احتياطيًا** (Console → Firestore → Rules) قبل النشر، فهذا الملف يستبدلها. القواعد الجديدة تحافظ على `users/**` للمالك.
4. `cd functions && npm install && cd ..`
5. نشر: `firebase deploy --only firestore:rules,firestore:indexes,functions`
   - المنطقة `europe-west1` مكتوبة في `functions/index.js` و`index.html` و`admin.html`؛ غيّرها في الثلاثة معًا إن أردت.
6. **Authentication:** تأكد أن Google مفعّل، وأن نطاق استضافة الصفحتين مُدرج في Authorized domains.
7. رفع `index.html` و`admin.html` إلى استضافتك الحالية (يمكنك أيضًا `firebase deploy --only hosting` إن أضفت إعداد Hosting).

## إنشاء حساب المدير الأول بأمان
1. سجّل الدخول مرة واحدة إلى التطبيق بحساب Google الذي سيكون المدير.
2. Console → Project settings → Service accounts → Generate new private key. احفظ الملف **خارج المشروع** ولا ترفعه إلى أي مكان.
3. `export GOOGLE_APPLICATION_CREDENTIALS=/path/key.json` ثم `node scripts/make-admin.js you@example.com`
   (يمنح الصلاحية ويزرع Basic/Pro/Office والإعدادات). لسحبها: `--revoke`. احذف المفتاح بعد الانتهاء.
4. افتح `admin.html` وسجّل الدخول. غير المدير يرى رسالة «غير مصرّح» وكل استدعاء له يُرفض من الخادم.

## الإدارة اليومية
- **الخطط والأسعار:** لوحة الإدارة ← الخطط. تغيير السعر يسري على الطلبات الجديدة فقط. عطّل الخطة بدل حذفها.
- **تعليمات الدفع:** لوحة الإدارة ← الإعدادات (لكل لغة). **ضروري قبل الإطلاق**: ما دامت فارغة لا يستطيع المستخدم إرسال طلب.
- **مراجعة المدفوعات:** ← طلبات الدفع ← «الإثبات» لرؤية الصورة/PDF، تأكد من وصول المبلغ فعليًا في حسابك، ثم «قبول» (تُحسب المدة تلقائيًا وتُراعى أيام الأشهر، وإن كان للمستخدم اشتراك سارٍ فالتجديد يُضاف بعد تاريخ انتهائه) أو «رفض» مع سبب يظهر له.
- **إجراءات يدوية:** ← المستخدمون: تفعيل، تمديد، تغيير الخطة، تعليق/رفع التعليق، إلغاء. الإيراد لا يُحسب إلا للمبالغ المؤكدة (> 0)؛ التفعيل المجاني والتمديد لا يُحسبان.
- **مدة السماح** افتراضيًا 0 (غيّرها من الإعدادات). **تعطيل فرض المزامنة:** أزل علامة «المزامنة السحابية تتطلب اشتراكًا».

## تنبيه مهم قبل الإطلاق
بمجرد نشر القواعد تتوقف **كتابة** المزامنة السحابية للمستخدمين الحاليين حتى يشتركوا (بياناتهم المحلية والسحابية تبقى سليمة وقابلة للقراءة). إن أردت فترة انتقالية: ألغِ علامة فرض المزامنة من الإعدادات، أو فعّل لهم اشتراكات يدويًا، أو ضع مدة سماح.

## الاختبارات
- `cd functions && node test-logic.js` — منطق التواريخ والملفات والحالات.
- `tests/rules.test.js` — قواعد الأمان بالمحاكي (أوامر التشغيل في أعلى الملف).
- التحقق اليدوي المقترح بعد النشر: سيناريوهات القائمة (1–14) من طلبك، خصوصًا محاولة `updateDoc` على `subscriptions/{uid}` من console المتصفح (يجب أن تفشل).

## ما لا يوجد (بصراحة)
- لا بريد إلكتروني ولا إشعارات دفع خارجية: الإشعارات داخل التطبيق فقط.
- لا بوابة دفع إلكتروني. أُعدّ المسار ليكون كل دفع «طلبًا» يُعتمد من الخادم؛ ربط بوابة لاحقًا يعني إضافة دالة webhook تستدعي منطق الاعتماد نفسه.
- حجم الإثبات 600 كيلوبايت (الصور تُصغَّر تلقائيًا) لأنها تُحفظ في Firestore دون الحاجة إلى Storage.
- لوحة الإحصاءات تقرأ كل السجلات: مناسبة لآلاف السجلات، وتحتاج تجميعًا مسبقًا لمئات الآلاف.
